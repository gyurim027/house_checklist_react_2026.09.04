## 1. 배경과 요청 사항

12개 SDD 태스크(Task 1~13, `.superpowers/sdd/immutable-squishing-lemon/`)로 완성된 체크리스트 앱에 대해, 사용자가 직접 관리하는 기능정의서(`04_house_checklist/기획서/기능정의서_v2.1.xlsx`)와 신규 제품 로드맵(`04_house_checklist/기획서/프로덕트 로드맵_0907.xlsx`)을 근거로 다음 확장을 요청했다.

1. 단일 스크롤 화면(온보딩 위저드 내부 상태 전환 + 체크리스트) → **react-router 기반 다중 페이지**로 분리. 기능정의서의 페이지 코드(`PA-XXX-NN`)가 다른 화면은 별도 라우트로 만든다.
2. **로그인 기능** 추가 — DB/백엔드 없이 프론트 전용 스텁. 카카오 버튼 1개만, 실제 인증 없이 홈으로 이동.
3. 기존 매물의 기본정보(주소/방문정보) 수정은 온보딩 라우트가 아니라 **체크리스트 화면 안에서 인라인**으로, 기본은 **접힌 요약 카드**로 표시.
4. 로그인 직후·홈 진입 전 **"선호 조건 선택" 온보딩**(12개 태그 다중선택, 스킵 가능, "마이"에서 재수정 가능)을 1회 추가.
5. 제품 로드맵의 **v1.0(내가 본 집+비교)**와 **v2.0(내 기준 설정/비교)** 슬라이스를 프론트 전용으로 앞당겨 구현 — 선택한 선호조건이 **매물 비교 화면에서 우선 비교**되도록 연결. 내비게이션에 "매물 비교"/"마이" 신설.
6. 기능정의서에 이미 표시된 소소한 변경(F-028 최종판단 라벨, F-034 새로고침 시 접힘상태 리셋, F-036 "체크 결과 복사" 삭제)도 함께 반영.
