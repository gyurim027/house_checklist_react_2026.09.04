## 1. 배경과 목적

`04_house_checklist/`에는 React 도입 전 순수 HTML/CSS/JS로 만든 부동산 임장 체크리스트 앱("집 보러 갈 때 10분 체크")이 있었다. 이 프로젝트(`C:\gyurim\02_house-checklist-react`)는 이 앱을 React(Vite 8 + React 19.2)로 다시 만드는 작업이다.

작업 착수 전 레거시 코드와 기획서를 직접 정독한 결과, **기획서(`04_house_checklist/기획서/*.md`)와 실제 동작하는 레거시 코드 사이에 괴리**가 있음을 확인했다:

- 실제 레거시 `app.js`가 구현한 것: 주소/별칭 입력, 매물 정보, 체크리스트(50문항, 3단계+해당없음, 메모), 카테고리 접기/펼치기, 진행률(확인율), 자동저장/수동저장, 저장 목록(불러오기/삭제).
- 기획서에는 있지만 레거시 코드엔 없던 것: **결과화면(점수·등급), 중개사 질문 목록, 최종판단**. 레거시 `scoring.js`는 "Phase 3에서 calcScore/calcGrade 등으로 확장 예정"이라는 주석만 남긴 채 확인율 계산까지만 구현되어 있었다.

## 2. 범위 결정 (사용자 확인 완료)

1. **범위**: 레거시가 실제로 하는 것 + 기획서에만 있던 결과화면/질문목록/최종판단까지 전부 새로 구현 (기획서 스펙 기준).
2. **제외**: 지도(Leaflet/Nominatim/GPS) 기능은 명시적으로 범위에서 제외.
3. **데이터 구조**: 레거시의 체크리스트 스키마(50문항, 9카테고리, 심각도, 상태값)와 저장 레코드 구조를 그대로 재사용.
4. **디자인**: 레거시 CSS는 재사용하지 않고 새로 디자인. 단, 기획서의 UX 규칙(색상 사용 규칙, 3분할 버튼, 단계적 노출 등)은 유지.
5. **상태관리**: 외부 라이브러리 없이 React 기본 훅 + localStorage. 라우터도 없음(단일 페이지, 내부 뷰 상태로 empty/inspection 전환).

### Task 3 — 저장소 레이어 (`5d04265`)

### Task 6 — 결과/점수 화면 (`b3f8c45`)

- **판단 사항(Ruling)**: 계획서의 Task 6 검증 예시("치명 1개 미흡 + 나머지 양호 → 92점")가 수학적으로 불가능한 값이었음을 발견(치명 감점 15점 고정이므로 1건만 미흡이면 최대 85점). Task 2 브리핑의 `calcGrade(92,1)` 단위 테스트 값을 실제 시나리오 검증에 잘못 재활용한 계획 오류로 판명. 구현자가 실제 도달 가능한 값(85점)으로 대체해 동일한 핵심 동작(치명 항목이 있으면 등급이 절대 "양호"로 뜨지 않는 것)을 검증. 컨트롤러가 이 대체를 타당하다고 판단하고 원장에 기록.
- **이연된 Minor 2건**: (1) 좋았던 점 목록의 React key가 index 기반 (2) 저장된 다른 매물로 전환 시 "결과 확인하기" 클릭 여부가 세션 상태로 남아있어, 이론상 완료율이 이미 60% 넘는 다른 매물로 전환하면 클릭 없이 바로 결과가 뜰 수 있는 엣지케이스(재현 검증은 안 됐음) — 최종 리뷰에서 재확인 예정.
