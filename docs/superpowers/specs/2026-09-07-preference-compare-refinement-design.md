## 원칙 충돌과 결정

이 프로젝트는 처음부터 **"DB/백엔드 없음, 프론트 전용"** 원칙으로 진행돼 왔고, `04_house_checklist/기획서/프로덕트 로드맵_0907.xlsx`의 v2.0 스코프가드에는 **"AI 자동 추천/절대 점수화는 제외"**가 명시돼 있었다(이 로드맵 문서를 근거로 v1.0/v2.0 슬라이스를 프론트 전용으로 앞당겨 구현하기로 결정했던 바로 그 문서).

사용자와 이 충돌을 확인한 결과: **Gemini API를 사용자 본인 API 키로 브라우저에서 직접 호출하는 방식**으로 진행하기로 결정했다. DB/백엔드는 여전히 없음(서버 프록시 없이 브라우저→Google API 직접 호출)이지만, 로드맵의 "AI 제외" 지침에서는 명시적으로 벗어난다 — 이 이탈은 사용자가 직접 확인한 의도된 결정이며, 로드맵 문서에도 버전업 시 반영한다.

### 1.2 반려동물 필드 구조화
- `questions.q_pet`의 값 타입을 자유텍스트(`string`)에서 **3지선다 enum**(`'yes' | 'no' | 'unknown' | null`)으로 변경.

- 영향 파일: `src/components/questions/RealtorQuestions.jsx`(렌더링), `src/data/checklistData.js`(QUESTIONS 정의에 `q_pet`만 타입 구분 필요 — 예: `{ id: 'q_pet', type: 'enum', options: PET_OPTIONS }` vs 나머지 7개는 기존처럼 텍스트), `storage.js`(기본값 `''` → `null`).
- 다른 7개 질문(q_internet, q_management_fee 등)은 변경 없음 — 자유텍스트 그대로.

## 2. 선호조건 재작업 (Task 19 리비전)

Task 19는 이미 구현·리뷰 완료됐지만, 다중선택 개수 제한이 빠져 있었다. 이번에 함께 고친다.

- `PreferenceTagGrid.jsx`: 5번째 태그 선택 시도부터 나머지 미선택 체크박스 비활성화("최대 4개" 안내 문구 + "n/4 선택됨" 카운터). 이미 선택된 항목은 언제든 해제 가능.
- `src/data/preferenceMap.js` 정리:
  - `pet` 태그: 매핑 대상은 그대로 `questionIds: ['q_pet']` — 단, 소비하는 쪽(Task 20의 비교 화면)이 이제 enum 값을 사람이 읽을 수 있는 라벨(가능/불가/문의 안 함/미답변)로 렌더링해야 함.
  - `size` 태그: `visitFields: ['areaPyeong']` 추가(기존 `itemIds: [furniture_space, closet_size, kitchen_space]`는 보조 프록시로 유지 — 실측 면적이 없을 때의 대체 신호).
  - `locationTransit` 태그: Task 19 리뷰에서 Minor로 남겨뒀던 문제 — 카테고리 전체(`B_parking_around`, 5문항) 대신 의도했던 2문항만 정확히 지정: `categoryIds` 제거, `itemIds: ['transit_walk', 'slope_stairs']`로 교체.
- `NavBar`: **체크리스트 화면(`PA-CKL-01`, `/checklist/:id`)에서는 하단 내비게이션(홈/마이, 추후 매물비교 포함)이 보이지 않아야 한다** — 체크리스트 작성 중 실수로 이탈하는 것을 막기 위함. `AppShell.jsx`가 현재 경로를 보고 `/checklist/:id`일 때만 `NavBar`를 숨기도록 조건부 렌더 필요(다른 AppShell 레이아웃 라우트 `/`, `/me`, `/compare/*`에는 계속 표시).

## 3. 매물 비교 — 결정적 로직 (AI 없이도 항상 완결)

기존 원칙(§5 매물비교설계, "사실 기반 비교", 새 합산 점수는 만들지 않음)을 그대로 유지한다.

- `PreferenceHighlightSection`은 선택된 선호조건 태그마다 매물별로 3상태를 판정한다:
  - **충족**: 매핑된 항목/질문 중 `poor`가 하나도 없고 `fine`/`great`/구조화된 긍정 답변이 있음.
  - **미흡 있음**: 매핑된 항목 중 `poor`가 하나 이상.
  - **미확인**: 매핑된 항목이 전부 미응답이거나 질문 답변이 없음.
- 매물별로 "선호조건 4개 중 n개 충족"을 표시 — 이것은 새로운 점수가 아니라 사용자가 이미 선택한 항목들의 **사실 요약**이며, 사용자가 점수와 선호충족을 직접 놓고 판단할 수 있게 돕는 보조 신호일 뿐이다.
- 이 레이어는 100% 결정적이며 AI/네트워크 없이 항상 동작한다.

## 4. Gemini AI 요약 (선택 기능)

**핵심 설계 원칙**: 없어도 비교 화면은 완전히 동작해야 한다. AI는 §3의 사실을 사람이 읽기 좋게 요약해줄 뿐, 새로운 판단 기준을 만들지 않는다.

### 4.1 API 키 관리
- `/me`(마이) 화면에 "AI 요약 설정(선택)" 섹션 신설. 비밀번호 타입 입력창 + 저장/삭제 버튼.
- 저장 위치: `houseChecklistReact.geminiApiKey.v1` (localStorage, 평문 — 이 앱의 다른 모든 데이터와 동일한 저장 방식). 안내 문구 필수: "이 키는 이 기기에만 저장되며, 비교 화면에서 Google API를 직접 호출하는 데만 사용됩니다. 서버로 전송되지 않습니다."
- 새 파일: `src/lib/geminiKeyStore.js`(get/set/clear, `authStub.js`와 동일한 스타일) 또는 `usePreferences`류 훅 하나 추가.

### 4.2 호출 흐름
- `/compare` 결과 화면에 "AI 요약 보기" 버튼 — **자동 호출 아님**, 클릭해야 API를 소모한다(사용자 쿼터 보호).
- 키 없음 → 버튼 대신 "마이에서 Gemini API 키를 등록하면 AI 요약을 볼 수 있어요" 안내 + `/me` 링크.
- 클릭 시: §3에서 이미 계산된 결정적 사실들(매물별 별칭/점수·등급[열람된 경우만]/선호조건 충족 현황)을 정리해 프롬프트로 구성, Gemini API(무료 티어 flash 계열 모델 — 정확한 모델명은 구현 시점에 Google 문서에서 최신값 확인 후 고정)에 직접 fetch. 프롬프트에 "한국어로 3줄 이내, 주어진 사실에만 근거해서 어떤 매물이 더 적합해 보이는지 요약. 새로운 정보를 추측하지 말 것"을 명시.
- 응답은 클라이언트에서도 3줄로 안전하게 자르고(모델이 지시를 무시할 경우 대비), 일반 텍스트로만 렌더링(마크다운/HTML 해석 안 함 — XSS 방지).
- 실패 처리: 네트워크 오류/쿼터 초과/키 오류 시 인라인 에러 메시지만 표시, 나머지 비교 화면(§3의 결정적 비교)은 완전히 정상 동작.
- 새 파일: `src/lib/geminiClient.js` — 순수 함수 `getComparisonSummary(facts, apiKey)`, fetch 캡슐화.
